# 재현·연구 설계

## 재현

먼저 목표를 구분한다: 코드 검토 / 최소 실행 확인 / 일부 결과 재현 / 주요 결과 재현 / 독립 구현 검증. 하나를 다른 수준의 성공으로 보고하지 않는다. 원저자 코드가 없다는 이유만으로 재현 불가라고 단정하지 않는다. 방법·데이터·자원이 충분하면 독립 구현 가능성을 검토하고, 필수 자료가 부족하면 현재 검증할 수 없는 범위와 필요한 자료를 구체적으로 설명한다.

1. 논문 버전·코드 commit·데이터 버전·라이선스·모델/의존성·환경·하드웨어를 확인한다.
2. 데이터 접근 권한, 전처리, split, seed, 학습/평가 조건, 결과 허용 오차를 정한다.
3. 실행 전에 필요한 자원·비용·시간·네트워크·파일 변경을 설명한다. 승인된 범위 밖 고비용 실행은 멈추고 확인한다.
4. 작은 smoke test부터 필요한 단계만 실행한다. 환경 설치 성공이나 코드 실행 완료는 논문 결과 재현 성공이 아니다.
5. 실행 명령·설정·실제 결과·실패·미실행 부분을 남긴다. 결과 차이는 보고 설정/환경/코드/데이터 차이와 통계 변동을 확인하기 전 부정행위나 논문 오류로 단정하지 않는다.

민감 데이터 원문이나 비밀키를 로그에 남기지 않는다. 타인의 데이터 업로드·라이선스 재배포는 별도 권한을 확인한다.

## 연구 설계

확인된 선행연구 한계와 제안 가설을 구분한다. 연구 질문 → 가설 → 방법 → 비교/대조 → 평가 → 반증 또는 중단 조건을 연결한다.

분야에 따라 표본/검정력, 데이터 수집·윤리, baseline, ablation, 평가 누수, 사전등록, 질적 타당성 또는 증명 전략을 검토한다. 모두를 모든 연구에 강제하지 않는다.

예상 효과는 가설로 표시하고 결과처럼 작성하지 않는다. 실험 설계와 실제 실행은 별개다. 대규모 실험·벤치마크나 참가자 모집을 자동으로 시작하지 않는다.

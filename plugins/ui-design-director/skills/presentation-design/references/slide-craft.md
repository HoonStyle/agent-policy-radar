# Slide craft and verification

## Composition and type

Start with the slide's main message and evidence. Decide the focal point, reading path, and relative visual weight. Prefer a deliberate grid and alignment over many equal boxes. Use scale, whitespace, and type to organize; decoration should contribute to the subject or template.

Preserve the source dimensions or requested aspect ratio. Check title, body, chart, legend, and footnote sizes at the audience's viewing scale. Microsoft suggests large readable presentation text; exact sizes still depend on canvas, viewing context, and the user's template. Split, clarify, or rearrange crowded content before making it unreadably small. Preserve required evidence and caveats.

Use appropriate glyph coverage for English and Korean. Review actual line breaks, fallback fonts, numerals, units, and punctuation after export. Do not make bilingual versions match by shrinking one language. Keep phrase-level grouping understandable, and choose separate versions unless side-by-side comparison serves the task.

## Color and imagery

Use theme colors and masters where supported, checking whether inherited overrides alter the intended result. Give chart series and categories consistent semantics; labels/patterns must carry distinctions without color alone. Shared UI palettes need adaptation for slides, projection, or print.

Use source-approved photos, diagrams, or illustrations that explain the material. Preserve evidence-bearing detail and aspect ratio. Avoid a full-slide raster export when editable content is required. Record asset provenance and factual sources in the project's normal citation/notes location.

## Evidence and accessibility

Check totals, units, dates, rounding, axis labels, and source scope. A native chart can still be wrong; editable does not mean accurate. Preserve underlying data lineage or formulas when the user requires them.

Give slides distinct navigable titles. Verify reading order, meaningful image descriptions, link text, and adequate contrast using the host's capabilities. Use simple data tables with clear headers; do not use complex tables as a layout engine. Decorative objects should not disrupt the reading order. Explain any semantic checks the tool cannot perform.

## Final pass

Record slide count and dimensions, inspect every slide individually, then scan the sequence. Look for clipped text, overlaps, weak hierarchy, mismatched fonts, unintended template drift, repeated filler, tiny sources, broken charts/tables, and missing content. Compare edited slides to the originals when preservation matters. Open in native PowerPoint only if available and within scope; report the actual application used.

These support the mechanics; aesthetic judgments still require inspection.

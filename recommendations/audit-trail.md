# 실행·지침 변경 감사 기록 제안

상태: 설계 제안. 자동 기록 기능은 미구현.

## 현재의 문제

CLI는 `reports/`, 최신 snapshot, 권고안 파일을 덮어쓴다. Git과 GitHub 릴리즈는 커밋된 코드 변경을 추적하지만 실행별 입력·실패·판단·사용자 승인을 증명하지 못한다. CHANGELOG도 승인 로그를 대체하지 않는다.

## 권장 기록 구조

설치 캐시 밖의 사용자 지정 저장소에 실행별 디렉터리를 만든다. 업데이트나 재설치로 기록을 잃지 않아야 한다.

```text
<user-data-dir>/agent-policy-radar/
  runs/<UTC-timestamp>-<uuid>/
    manifest.json
    inventory.json
    source-results.json
    findings.json
    recommendations.json
  events/<uuid>.json
```

- 파일을 배타적으로 생성해 기존 실행·이벤트를 덮어쓰지 않는다.
- 불완전 실행은 running/failed로 남기며 성공 처리하지 않는다.
- latest 참조는 편의를 위한 것으로 원본 기록이 아니다.
- 외부 업로드·Git 추적은 기본 비활성. 원문 저장 없이 해시와 최소 메타데이터가 기본이다.

## 실행 manifest

- schema_version, run_id, UTC 시작/종료 시각, 상태
- 도구 버전/커밋, dirty 여부, OS/Python 버전
- 실행 단계, 설정 해시, 발견/누락/제외/읽기 실패 파일 수
- 입력 식별자와 SHA-256, 산출물 해시
- 공식 URL별 최초 수집/변경 없음/변경/실패를 구별
- 의미 분석 사용 시 모델/제공자·비용·실패·외부 전송 승인 참조. API 키나 원문 요청 로그는 저장하지 않음

## 변경 이벤트 연결

`run_id → recommendation_id → approval_id → application_id → verification_id`

- 제안: 근거 실행, 대상, 변경 사유, 제안 patch hash, 한계.
- 승인: 사용자 승인 경로/시각/명시 범위, 대상 및 patch hash. 일반적인 대화 동의를 전체 파일 변경 승인으로 확장하지 않음.
- 적용: 실제 대상의 변경 전/후 해시, 적용 커밋, 결과. 승인 이후 원본 또는 patch가 달라지면 재승인.
- 검증: 실행 명령/테스트 식별자, 결과, 미실행 항목. 실패·취소·철회·롤백은 별도 이벤트로 추가.
- 지금 도구는 자동 적용 기능이 없으므로 다른 프로젝트에서 수동 적용한 결과는 증거를 참조하는 수동 기록으로 구분.

## 안전과 보존

- 감지된 중복은 삭제 승인이나 하네스 우선순위의 증거가 아니다.
- 설치 skill의 안전 규칙은 다른 하네스에서 전역 규칙이 로드되지 않을 수 있으므로 중복만으로 축약하지 않는다.
- MCP 설정은 인증정보를 담을 수 있음: 임의 config/cache 전체 수집 대신 명시적으로 지정한 instructions 필드/파일만 대상으로 제한.
- 개인 파일 원문과 전체 사적 대화는 감사 기록에 기본 저장하지 않는다. 로컬 산출물에도 접근권한 제한 적용.
- 보존 기간·삭제는 사용자 설정/승인으로 정하며 자동 무기한 수집하지 않는다.
- 해시와 append-only 운영만으로 위변조 방지/법적 감사 보장을 주장하지 않는다. 동일 사용자가 수정 가능하며 독립 서명·외부 보관은 별도 설계다.

## 구현 및 검증 순서

1. 설치 캐시와 분리된 `--data-dir`, 사용자 설정 경로 지원.
2. 실행별 디렉터리/manifest와 모든 실패 상태 기록.
3. 제안 ID 및 승인/수동 적용 이벤트 기록 CLI 추가. 실제 정책 자동 수정은 계속 금지.
4. 고정 fixture로 두 번 실행 시 이전 기록 보존, 동시 실행 ID 충돌 없음, 실패 기록, 민감 원문 미포함을 테스트.
5. 승인 patch/대상 불일치와 Windows/macOS 경로를 검증한 후 릴리즈.
